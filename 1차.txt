# ON BOARD — 무역 시뮬레이터 MVP 구현 프롬프트

무역거래를 게임처럼 직접 체험할 수 있는 웹앱 **「ON BOARD」**의 MVP를 만들어줘.

## 1. 서비스 개요

서비스 이름은 **ON BOARD**.

핵심 콘셉트:

> **무역거래에 직접 올라타다.**

사용자가 한국 수출기업의 무역 담당자가 되어 미국 바이어와 가상의 수출거래를 진행한다.

사용자는 거래 과정에서 직접 의사결정을 한다.

* 거래조건 선택
* Incoterms 선택
* 운송수단 선택
* 결제조건 선택
* 보험 가입 여부
* 환율 확인
* 수출비용 계산
* 거래 과정에서 발생하는 오류 확인
* 최종 거래 결과와 점수 확인

단순한 계산기가 아니라 **교육 + 시뮬레이션 + 게임**의 성격을 가진 웹앱으로 만들어줘.

---

# 2. 기술 스택

다음 기술을 사용해줘.

* React
* Vite
* JavaScript 또는 TypeScript
* Tailwind CSS
* Lucide React Icons

백엔드와 로그인은 MVP에서 구현하지 않는다.

모든 데이터는 프론트엔드 상태로 관리한다.

새로고침하면 초기화되어도 괜찮다.

---

# 3. 전체적인 디자인 방향

전체적인 분위기는

**현대적인 글로벌 물류/금융 대시보드 + 게임 UI**

느낌으로 만들어줘.

너무 복잡한 기업용 ERP처럼 만들지 말고, 대학생이 처음 사용해도 직관적으로 이해할 수 있도록 만들어줘.

### 디자인 키워드

* Modern
* Minimal
* Professional
* Global
* Trading
* Logistics
* Simulation
* Gamified

### 색상

메인 색상은 짙은 네이비/블루 계열을 사용한다.

배경은 밝은 회색 또는 거의 흰색.

중요한 액션 버튼은 블루 계열.

성공은 green 계열.

경고는 amber 계열.

오류는 red 계열.

색상을 과도하게 사용하지 않는다.

# 9. STEP 01 — 거래조건

제목:

## 어떤 거래조건으로 계약하시겠습니까?

간단한 설명:

> 수출자와 수입자가 각각 부담할 비용과 위험의 범위를 결정합니다.

선택지는 카드 형태로 보여준다.

* EXW
* FOB
* CIF
* DDP

MVP에서는 우선 4개만 구현한다.

각 카드에 마우스를 올리면 간단한 설명을 보여준다.

예:

FOB
Free On Board

판매자가 물품을 본선에 적재할 때까지의 주요 비용과 위험을 부담합니다.

사용자가 하나를 선택하면 선택 카드가 강조된다.

NEXT → INCOTERMS

# 11. 오류 탐지 기능

이 서비스의 핵심 기능 중 하나다.

사용자가 선택한 조건과 이후 선택이 충돌하면 경고를 보여준다.

예를 들어:

사용자가

FOB

를 선택하고

컨테이너 운송

을 선택하면 다음과 같은 경고를 표시한다.

### ⚠️ 거래조건 검토 필요

FOB는 본선 적재를 기준으로 위험이 이전되는 조건입니다.

컨테이너 화물은 실제 선적 전에 운송인에게 인도되는 경우가 많기 때문에 FCA가 더 적절할 수 있습니다.

버튼:

UNDERSTAND

이 경고는 거래를 막지는 않는다.

학습을 위한 피드백이다.

# 14. STEP 05 — 보험

제목:

## 화물보험에 가입하시겠습니까?

선택:

YES
NO

보험료율:

0.3%

보험 가입을 선택하면 자동으로 보험료를 계산한다.

보험금액은 간단하게 다음 기준을 사용한다.

Contract Value × 110%

보험료:

Insurance Amount × 0.3%

계산 결과를 즉시 보여준다.

예:

Insurance Amount
USD 110,000

Insurance Premium
USD 330

CIF를 선택한 경우 보험 가입을 추천하는 메시지를 표시한다.

제목:

₩138,000,000

예:

# 23. 중요한 UX

사용자가 현재 무엇을 해야 하는지 항상 명확해야 한다.

각 단계마다:

STEP 번호

↓

질문

↓

선택지

↓

현재 선택

↓

간단한 설명

화면을 복잡하게 만들지 않는다.

모바일과 데스크톱 모두 반응형으로 만든다.

# 24. 애니메이션

과도한 애니메이션은 사용하지 않는다.

다음 정도만 구현한다.

* 페이지/STEP 전환 fade
* 카드 hover
* 선택 카드 강조
* progress bar transition
* 결과 숫자 count-up 효과
* 성공 화면의 간단한 animation

---

# 25. 오류 처리

사용자가 잘못된 선택을 했다고 거래를 중단시키지 않는다.

대신:

⚠️ REVIEW REQUIRED

형태로 알려주고 계속 진행할 수 있게 한다.

이 앱은 시험 문제가 아니라 **실제 무역 의사결정을 체험하는 시뮬레이션**이기 때문이다.

---

# 26. MVP에서 하지 않을 것

다음 기능은 구현하지 않는다.

* 로그인
* 회원가입
* 데이터베이스
* 실제 환율 API
* 실제 운임 API
* 결제 시스템
* 실제 무역거래
* 외부 API
* 관리자 페이지
* 실제 L/C 발행
* 실제 선하증권 발행

모든 데이터는 가상의 시뮬레이션 데이터로 처리한다.

---

# 27. 최종적으로 느껴져야 하는 서비스

사용자가 처음 들어왔을 때:

> "이건 무역 공부 사이트네."

가 아니라

> **"내가 진짜 무역회사 직원이 돼서 거래를 진행하는 게임이네."**

라는 느낌이 들게 만들어줘.

하지만 각 선택에는 실제 무역 개념이 연결되어 있어서 플레이하면서 자연스럽게 무역영어와 무역실무를 학습할 수 있어야 한다.

# 29. 가장 중요한 요구사항

**실제로 클릭해서 처음부터 끝까지 거래를 완료할 수 있어야 한다.**

다음 흐름이 반드시 작동해야 한다.

HOME
→ NEW TRADE
→ START TRADE
→ CONTRACT
→ INCOTERMS
→ SHIPPING
→ PAYMENT
→ INSURANCE
→ FX
→ COST
→ RESULT

그리고 사용자가 선택을 변경하면 이후 계산값과 결과가 자동으로 변경되어야 한다.

모든 버튼은 실제 동작해야 하며, 단순한 디자인 목업만 만들지 않는다.

먼저 MVP 전체를 구현한 뒤 실행 오류가 없는지 확인하고, 마지막으로 UI의 간격·정렬·반응형·버튼 상태 등을 정리해 완성도 높은 프로토타입으로 만들어줘.
