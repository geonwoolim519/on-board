# ON BOARD 2.0 — Multi-Trade Simulation Platform

현재 구현되어 있는 **ON BOARD 무역 시뮬레이터 MVP를 대폭 확장해줘.**

기존 MVP는 한국 → 미국 자동차 부품 수출이라는 하나의 시나리오에 제한되어 있고, Incoterms도 일부 조건만 제공하고 있다.

이번 업데이트에서는 ON BOARD를 단일 시나리오가 아니라 **다양한 국제무역 거래를 반복해서 플레이할 수 있는 무역 시뮬레이션 플랫폼**으로 발전시킨다.

기존 UI 디자인과 브랜드 아이덴티티는 유지하되, 데이터 구조와 거래 시스템을 확장해 재사용 가능한 구조로 리팩터링한다.

---

# 1. 핵심 목표

ON BOARD의 핵심 경험을 다음과 같이 변경한다.

기존:

> 한국 → 미국 자동차 부품 수출

변경:

> **사용자가 다양한 무역거래 중 하나를 선택하고 직접 거래를 진행**

사용자는 거래마다 서로 다른

* 국가
* 도시
* 항구
* 기업
* 품목
* 수량
* 계약금액
* 통화
* 운송수단
* Incoterms
* 결제조건
* 보험
* 환율
* 비용
* 리스크

를 경험할 수 있어야 한다.

즉,

**한 번 플레이하고 끝나는 앱이 아니라 여러 거래를 반복해서 플레이하는 게임**으로 만든다.

---

# 2. 가장 중요한 구조 변경

거래 데이터를 UI 코드에 하드코딩하지 않는다.

모든 거래는 **Scenario Data**로 관리한다.

예를 들어:

```text
scenarios/
├── korea-usa-auto-parts
├── korea-japan-electronics
├── china-korea-textiles
├── germany-korea-machinery
├── korea-vietnam-food
├── usa-korea-semiconductor
└── ...
```

또는 하나의 JSON/JS 데이터베이스 형태로 관리해도 된다.

핵심은 **새로운 거래 시나리오를 데이터만 추가해서 확장할 수 있는 구조**를 만드는 것이다.

# 5. 항구 데이터베이스를 별도로 구축

항구를 특정 시나리오에 하드코딩하지 않는다.

다음과 같은 Port Data를 만든다.

예:

```text
Busan
Incheon
Gwangyang

Los Angeles
Long Beach
New York
Savannah

Yokohama
Tokyo
Osaka

Shanghai
Ningbo
Shenzhen

Hamburg
Rotterdam
Antwerp

Singapore
Ho Chi Minh
Jebel Ali

Dubai
```

각 항구에는 최소한 다음 정보를 저장한다.

* name
* country
* city
* code
* region
* transportType
* baseFreightMultiplier

예:

```text
Busan
Country: South Korea
Code: KRPUS
Region: Asia
```

실제 항만 코드가 불확실한 경우 임의의 코드를 만들어내지 말고 검증 가능한 값만 사용한다.

# 11. Incoterms 적용 범위 검증

매우 중요한 기능.

사용자가:

FOB

를 선택한 뒤

Air Freight

를 선택하면 단순 경고가 아니라:

### ⚠ INCOTERMS MISMATCH

FOB는 해상운송 및 내수로 운송에 사용되는 조건입니다.

현재 선택한 운송수단은 항공운송입니다.

이 거래에서는 FCA와 같은 모든 운송방식에 사용할 수 있는 조건을 검토해보세요.

라고 표시한다.

# 12. 다른 Incoterms에도 논리 적용

다음과 같은 기본 검증 로직을 구현한다.

### EXW

판매자의 부담 범위가 가장 작음.

### FCA

모든 운송방식 사용 가능.

### CPT

운송비는 판매자가 부담하지만 위험은 운송인에게 인도할 때 이전.

### CIP

CPT + 보험.

### FAS

해상/내수로 운송.

### FOB

해상/내수로 운송.

### CFR

해상/내수로 운송.

### CIF

CFR + 보험.

### DAP

목적지까지 운송하지만 unloading은 매수인 부담.

### DPU

목적지에서 unloading까지 매도인 부담.

### DDP

수입통관 및 관세 등을 포함하여 매도인의 부담 범위가 가장 큼.

각 조건에 대한 상세 법률/계약 해석을 과도하게 단순화하지 말고, UI에서는 교육용으로 이해하기 쉽게 표현한다.

# 20. 보험 시스템

Incoterms와 연결한다.

CIF / CIP 등 보험이 포함되는 조건에서는 보험료를 자동 계산한다.

보험이 포함되지 않는 조건에서는 사용자가 별도로 보험 가입 여부를 선택할 수 있다.

보험료율은 시나리오마다 다르게 설정할 수 있도록 한다.

예:

0.2%

0.3%

0.5%

보험금액은 시뮬레이션 규칙에 따라 계산한다.

현재 구현되어 있는 계산 로직을 유지하되, 특정 거래 하나에 종속되지 않도록 리팩터링한다.

# 22. Seller Cost / Buyer Cost 시각화

비용 계산 화면에:

## SELLER

총 부담비용

₩XX,XXX,XXX

---

## BUYER

총 부담비용

₩XX,XXX,XXX

를 보여준다.

그리고:

### TOTAL TRADE COST

전체 거래에 들어가는 비용

도 별도로 보여준다.

이렇게 하면 Incoterms를 선택했을 때 비용 부담 구조가 실제로 어떻게 달라지는지 체감할 수 있다.

# 23. 관세 시스템

DDP 등의 조건을 제대로 체험할 수 있도록 간단한 관세 시스템을 만든다.

각 시나리오에:

dutyRate

를 저장한다.

예:

3%

5%

8%

사용자가 DDP를 선택하면 시뮬레이션상 수입관세 부담이 Seller 측 비용에 포함되도록 한다.

단, 실제 국가별 관세율을 제공하는 서비스라고 오해하지 않도록:

> **Simulation Data**

라는 표시를 붙인다.

# 35. Incoterms 적합성 점수

선택한 거래조건과 운송방식, 거래구조를 기반으로:

### INCOTERMS FIT

Excellent
Good
Review Required
Mismatch

중 하나를 보여준다.

예:

FOB + Sea

→ GOOD

FOB + Air

→ MISMATCH

FCA + Air

→ GOOD

CIF + Sea

→ GOOD

이 로직은 단순한 문자열 비교가 아니라 **Incoterms의 적용 운송방식 데이터**를 기준으로 구현한다.

# 53. 핵심 철학

ON BOARD는 단순한:

> **무역 계산기**

가 아니다.

또한 단순한:

> **무역영어 퀴즈 앱**

도 아니다.

목표는:

> **“내가 실제 무역 담당자라면 어떤 결정을 내려야 할까?”**

를 경험하는 것이다.

사용자가 여러 국가와 여러 품목을 거래하고, 11개의 Incoterms를 직접 사용해보며, 운송·결제·보험·환율·비용·리스크 사이의 관계를 이해할 수 있는 **Trade Simulation Platform**으로 발전시켜줘.

기존 ON BOARD의 기능과 디자인을 먼저 분석한 뒤, 기존 기능을 깨뜨리지 않는 방식으로 확장한다.

**코드보다 데이터 구조와 재사용성을 우선한다.**

새로운 거래를 추가할 때 UI 코드를 수정하지 않고 Scenario Data만 추가해도 새로운 거래가 생성될 수 있는 구조를 최우선으로 한다.

마지막으로 실제로 다음 테스트를 수행한다.

1. Korea → USA 거래 완료
2. Korea → Japan 거래 완료
3. Germany → Korea 거래 완료
4. FOB + Sea 정상 작동
5. FOB + Air 경고 작동
6. CIF + Sea 보험 자동 계산
7. DDP에서 수입통관/관세 비용 반영
8. 11개 Incoterms 모두 선택 가능
9. 환율 변경 시 비용/이익 변경
10. 항구 변경 시 운송비 변경
11. 거래 완료 후 History 저장
12. 모바일 화면에서 모든 거래 과정 정상 작동

모든 테스트를 완료하고 기존 기능에 오류가 없는 상태로 마무리해줘.
